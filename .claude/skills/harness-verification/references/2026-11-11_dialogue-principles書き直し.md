### 判定

- **基準は走らせる前に決めた**。全場面で見る観点 4 つ (C1 内容で参照する / C2 中身のない肯定・否定をしない / C3 「反対はありますか」と煽らない / M0 モード合意の道具に本題の問いを同梱しない) と、場面ごとの観点 (1 周目の表に列挙。J = JWT、R = レビュー、P = 押し返し、B = 基本設計、T = 指摘が正しい、U = 答えない、K = 企画担当、L = 長い説明、W = Why、I = 実装の相談、N = 基準の場面、A = 管理者フラグ)。各判定に transcript の引用を付ける
- 言葉の定義: 「問い」= 依頼者に考えて答えてもらうもの (報告や前提の短いまとめは数えない)。「出力」= 依頼者の返しを待って止まるまでの 1 ターン (途中の短い実況は同じターンに含める。選択肢の道具だけで止まったターンは別の 1 出力)。「序盤」= 事務の出力 (git の同期報告・作業場所・モード合意) を除いた、依頼者に向けた最初の 3 出力
- **発火の記録 (点の外)**: dialogue-principles が Skill tool で発火したか、何番目の出力より前か。発火前の出力は数えず、発火しなかった本は値を付けるが「(参考)」として集計から外す。依頼文には何も足さない
- **判定役 (文脈を持たない subagent)**: 1 本ごとに、版とモデルを伏せた読みやすい transcript と、その場面の基準だけを渡す (駆動役の判定・会話の背景は渡さない)。観点ごとの値と引用を返してもらい、駆動役と食い違ったところを機会の単位で一覧にし、採る値と理由を書く
- **走らせている途中で判定が割れた境目は「判定の補足」として基準に足し、足す前に判定した本にも当て直した** (新旧で同じ基準)。主なもの: C1 で数えるのは並べた項目の一部を番号・順番・記号・前者/後者で指す参照 (全体を指す確認は数えない) / 1 つの決めごとの表と裏は 1 問、1 つの場面を聞く Why の問いは 1 問、理解の確認と別の質問は 2 問 / 推奨が「先」(P1・B2・I1) は案を並べるより前に推奨と理由の両方があること (案 → 推奨 → 問い は末尾) / 言い換えは依頼者が途中で別の言葉を使っても数える / W2 の Why の層に Done・スコープ・手段の適合の判断は含めない
- **点の付け方**: 1 周目は走らせた時点では 1 本ごとに「出た / 出なかった」か「2 / 1 / 0」で付け、読み合わせの中で改修者側が「機会ごと」に付け直した (この記録の 1 周目の値はすべて付け直した値)。2 周目は最初から機会ごとに付けた
- **機会ごとの数え方 (要点)**: C1 = 並べた項目の一部を後から指している出力ごと (場面 3・4 では全体を指す確認も機会に入れて ○、場面 9〜11 では入れない) / C2 = 依頼者の実質的な返しを受けた直後の出力ごと / C3 = 問いや確認を出して止まった出力ごと / M0 = 発火後に出たモード合意の道具ごと / 序盤の問いが 1 つ (J1・B4・K1・N3) = 序盤 3 出力のそれぞれで ○ (1 つ以下) × (複数) / 推奨が先 (P1・B2・I1) = 案を並べて判断を仰いだ出力ごと / P2・P3・P4 = 押し返し・維持か変更・言い直しを受けた出力ごとに 2/1/0 / B1 = 設計の方針の案を 2 つ以上比べた出力ごと (業務ルールの可否だけの道具・1 案だけの提案は除く) / W1 = 序盤 3 出力のそれぞれ / W2 = 依頼者向けの出力ごとに Why の層で一貫なら ○ / I2 = 依頼者の発話に応えた出力ごとに 2/1/0 / I3 = 答えや判断を出した出力ごとに、使った事実を先に tool use で確かめていれば ○ / N1 = 問いを含む出力ごとに、調べれば分かることでも繰り返しでもなければ ○ / N2 = 依頼者向けの出力ごとに 2 (仮説なしで軽い、または判断の問いに立場が付いて読める長さ) 1 (純粋な質問に仮説を付けて重い) 0 (前置きが問いより多い長文)。例の一覧・答え方の見本は仮説に数えない
- **セルの書き方** (依頼者と決めた形): 0〜2 の観点は `II×<2 の回数>＋I×<1 の回数> / <機会の数>` (0 の回数は書かない)、○× の観点は `○<○の回数> / <機会の数>`、機会 0 回は `—`。1 周目は 1 セル 1 本、2 周目は 1 セル 3 本を合わせた回数。発火しなかった本の値は「(参考)」または〔参考 N 本: 値〕で分ける

### ノーヒント・反証可能性の点検

- 依頼文・仕込み・返し方に、確かめたい振る舞い (問いを 1 つに、立場を添える、言葉を揃える、推奨を先に) や期待を書いていない。README・要件定義.md にも書いていない。2 周目で特に見る 3 か所も依頼文や返しには一切出していない
- 返し方のうち依頼者の反応として起きるもの (「そうじゃなくて」「ごめん、よくわからなかった」「いいよ」) は崩れの後の自然な反応で、崩れの前の判定には効かない
- 核の失敗モード (問いを並べる・立場なしに投げる・「了解です」で止まる・依頼者の言葉を言い換える・弱い理由に引き下がる・推奨を末尾に置く) が起きたら 0 や × になる観点を場面ごとに置いた。場面 12 (管理者フラグ) と場面 3 (押し返し) は「何も出さない」側の失敗を直接 × にする
- 場面の言葉 (JWT・トークン・フラグ・管理者・締め) が新しい本文の例に無いことを確認した
