# 対話原則の書き直し — 検証の駆動役への依頼

> 基本設計の対話をした main session が、検証を駆動する別セッション (端末を分けるツールのペインで開く) に渡す依頼。実装後もそのまま残す。

あなたは、`dialogue-principles` の書き直しを検証する **駆動役** です。main session (この依頼を送ったセッション) は、本文を書くことと結果の判断を持ちます。あなたは検証を組み立てて走らせ、結果を返します。

## 最初に読むもの

- `docs/working/対話原則の書き直し/要件定義.md` (Why と Done)
- `docs/working/対話原則の書き直し/基本設計.md` の「4. 確かめ方」(場面 12 個、比べ方と回数、点数の付け方、周の回し方、進め方、駆動役が走らせる前に作るもの、セッション間のやり取り) — **これがあなたの仕様**
- `.claude/skills/harness-verification/SKILL.md` — 検証の手順そのもの。**`harness-verification` skill を呼んで** から進める (同梱スクリプトだけを直接叩かない)
- 対話の手本 — 判定役に渡す、判定の境目の手本。公開しないファイルなので、この作業ツリーには無い。場所は main session が依頼のメッセージで伝える

## やること (順番)

1. 基本設計の「駆動役が走らせる前に作るもの」を作る: 場面ごとの仕込み・最初の依頼文の全文・依頼者役の返し方・1 本の終わり方・判定の基準・新旧の deploy のやり方
2. それを main session に送り、確認を取る (main session が見たあと、依頼者にも見せる)。**確認が取れるまで走らせない**
3. まず数場面だけ走らせて、条件の不備を見つける。不備があれば直して main session に報告する
4. 12 場面 × 新旧 × 2 モデル (Opus 5.5 / Sonnet 5.5) を 1 回ずつ走らせる。ぶれる場面は同じ条件で何回か追加してよい
5. 各回、dialogue-principles が発火したかを記録し、発火しなかった回は点数から外して別に数える
6. 判定は、会話の文脈を持たない subagent にもさせる (渡すのは transcript・判定の基準・対話の手本だけ)。あなたの判定と食い違ったところは一覧にする
7. 結果を main session に送る (返す中身は基本設計の「セッション間のやり取り」)
8. 検証記録を `.claude/skills/harness-verification/references/` に、`references/README.md` の書式で残す (`verdict` は「新旧比較・合否線なし」と、上がった観点・下がった観点の要約)

## 固定する版

- 新しい版: main session が送る依頼メッセージに書く commit

## 守ること

- ノーヒント: 依頼文・仕込み・依頼者役の返し方に、確かめたい振る舞いや期待を書かない
- `claude -p` (ヘッドレス) は使わない
- 点数は「4 回中 3 回」のように回数で出し、小数にしない
- 依頼者役は、聞かれたことにだけ短く答える
- dialogue-principles 本文やフェーズ側の skill は書き換えない (直すのは main session)
- push・PR 作成はしない
- main session への問い合わせは、走らせる前の確認・仕込みが場面として成り立たないと分かったとき・判定の基準で迷ったときに限る。それ以外は自分で判断して進める
