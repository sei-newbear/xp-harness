# 省略しないと一つずつ短くを同じ重さにする

## 背景 / Why

実作業セッションのふりかえり (2026-10-30 受領) で、「長すぎる」「一度に複数の論点を出す」「何が分かっていないかを聞かずに長く解説する」「記号 (A・B) で話す」という種類の指摘が、セッションの最初から最後まで続いた。dialogue-principles を読み込んだ直後でも「長すぎ」と言われていた。

分析 (推測): dialogue-principles の「出力の規律」で「★最重要」とされているのは規律 1「省略しない、内容で書く」(system prompt の「短く簡潔に」を上書きする宣言とセット)。「長さは仕事量ではない」「発散時は各候補を短く」は後ろの節 (ズレを検知したら止める、発散と収束のリズム) にある。エージェントは「省略しない」を一番強く受け取り、漏れなく多く書くことを優先して、長く・同時に複数の方向に振れた。

読み込んだ直後でも崩れていたので、発火 (読み直し) の問題ではなく、書いてある中身の読まれ方の問題として扱う。読み直しの発火は既存カード「対話モード中の対話原則の継続注入」の範囲。

改修セッション (2026-10-31) でも再現: main session が既存の規律を引用したうえで自分の言葉で言い直し、同じ話を二回書いて依頼者に「同じ文章繰り返してない？」と指摘された。

## 状況

方向 (依頼者と合意済み):

- 「省略しない」は指示語・番号・記号を使わないことであって、量を増やすことではない、と冒頭で切り分ける
- 「一つずつ・短く」を「省略しない」と同じ重さに置く (今は後ろの節に散っている)

## 再開時の起点

1. dialogue-principles 本文の「出力の規律」冒頭 (system prompt 上書きの宣言、規律 1) と、「ズレを検知したら止める」「発散と収束のリズム」「段階的開示」を読み、重さの置き方を設計する
2. 対話の振る舞いに効く改修なので、harness-verification で確かめる (「省略しない」を守ったまま、長さと論点の数が抑えられるか)
