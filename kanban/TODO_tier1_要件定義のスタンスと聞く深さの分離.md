# 要件定義のスタンスと聞く深さの分離

## 背景 / Why

アジャイルの練度が高いチームが、既に小さく分割したストーリーを渡しているのに、`define-requirements` がフルの要件定義で入って過剰になる。

過剰さの正体は質問の量ではなく **姿勢**。依頼を仮説として扱って前提を覆しに行く姿勢が、どのセクションにも混ざる。なぜやるかを聞くこと自体は問題ない。掘った結果で代案を出す・前提を問い直すところまで行くのが過剰で、「間違えずに進むために確認する」姿勢なら同じことを聞いても重くない。

## 状況

`define-requirements` は本文最上段にモード合意ゲートを持ち、モードは 3 つ (モード未確定 / 対話モード / 自走モード)。問題は、2 つの実モードが **スタンスと聞く深さをセットにしている** こと:

- 対話モード = 疑う + 深く聞く (Why を掘り、Why と解決策がズレたら代案を提案する)
- 自走モード = 疑わない + 聞かない (最小限だけ口頭で揃えて実装に渡す、要件定義.md も作らない)

求められているのは「疑わない + 理解できるまで聞く」で、この組み合わせが今は存在しない。

さらに見立ての目安が「解決策の指定は深掘る理由になりうる」「迷ったら対話モード側を推奨」なので、小さく分割されたストーリーは対話モードに振られやすい。

## 再開時の起点

モードの軸を「依頼を仮説として扱うか / 決定として扱うか」というスタンスに置き直せるか検討するところから。聞く深さはスタンスから切り離し、モードで固定せず対話の中で決まるものとして扱えるかを見る。

前提として壊さないもの:

- 既存のモード合意ゲートの構造 (帰結ある行動の手前で 1 回だけ、非破壊な動き = 調査・議論はノーゲート)
- DONE カード「define-requirements の入口をモード合意ゲート化」「軽量依頼で要件固めをスキップ確認する」で作った動線

`philosophy` の判断軸「対話と自走の境界」にも対話モード / 自走モードが書かれているので、軸を変えるならそちらとの整合も見る。

挙動に効く改修なので `harness-verification` での確認が要る。
