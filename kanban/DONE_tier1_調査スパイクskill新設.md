# 調査スパイクskill新設

完了 (2026-08-06、v0.18.0 でリリース)。調査・スパイクを「問いに答える」でなく「判断の危険を潰す」まで走り切る `research-spike` skill を新設した。

作り物の題材による初回検証は通ったが、実プロジェクトで使ったところ体感が「全然ダメ」だった。本番セッションを transcript で分析したところ、明文の要求はほぼ満たしていたのに入口が崩れていた ── 依頼から 3 分で確かめどころ 21 項目を建て、依頼者が「認識ずれてる」と書いた 25 秒後に自分で「合意できました」と宣言して自走に入っていた。緩かったのは止まる点ではなく通過判定だった。

入口を組み替えた。土台 (何を決めるための調査か / 既に調べたこと / 動かせない条件) を幹から枝の順に一つずつ聞き、途中でゴールの像を返して直してもらう。確かめどころは出し切ってファイルに見せ、依頼者の同意を受け取ってから自走に入る。合意は自分で宣言しない。

同じ依頼文を sandbox に再投入して検証し、入口の 4 手順すべてを観測、計画合意から報告まで走り切ることを確認した (旧ランが既知の FAIL として対照)。

分析・検証の記録は `.claude/skills/harness-verification/references/` の 3 本 (初回動作検証 / 本番セッション分析 / 入口改修の再現ラン)、要件・設計は `docs/working/調査スパイクskill/` にある。

入口以外に未対応の論点が 3 つ残っている (調べたことの記録先が引き継ぎ文書と両立しない / 「依頼者が達成を認めた」型の終わりが本文に無い / 報告の後の会話が出口の節の範囲外)。カード化はせず、検証記録に残してある。次の実運用で痛みが再発したら起こす。
